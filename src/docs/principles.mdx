# Design Principles

หลักการ 6 ข้อสำหรับ OMS และ Internal Tools ใช้ตัดสินเมื่อแนวทางในเอกสารไม่ครอบคลุม

### 1. ข้อมูลมาก่อน ตกแต่งน้อย
พื้นที่ส่วนใหญ่ของหน้าเป็น **ขาว (#FFFFFF)** และ **Secondary (#F3F7FA)** ใช้ **Primary (#045275)** เฉพาะการกระทำหลัก ลิงก์ และสิ่งที่ถูกเลือก
แต่ละบริเวณมีปุ่ม primary **ไม่เกิน 1 ปุ่ม** และใช้เส้นขอบแทนเงา
*ตัวอย่าง:* หน้ารายการคำสั่งซื้อมีปุ่ม “สร้างคำสั่งซื้อ” เป็น primary ส่วน “ส่งออก” เป็น outline

### 2. สแกนได้เร็ว
ตัวเลขและยอดเงินชิดขวาและใช้ tabular-nums · รหัสและ ID ใช้ฟอนต์ mono · ใช้รูปแบบเดิมทุกหน้า เพื่อให้ตาจำตำแหน่งได้
*ตัวอย่าง:* `SP2510300O01` ในฟอนต์ mono ทำให้แยก 0 กับ O ได้ทันที

### 3. สถานะชัด ไม่รวมกัน
สถานะใช้ **สีและข้อความ** เสมอ ห้ามใช้สีอย่างเดียว · แสดงสถานะงานแยกจากป้ายข้างเคียง (blocker, ยกเลิกจากช่องทาง, มีโน้ต) ตามกฎ OMS B.2-9
*ตัวอย่าง:* `รอตรวจสอบ` + `ลูกค้ายกเลิก` เป็น 2 ป้าย ไม่ใช่ “รอตรวจ-ยกเลิก”

### 4. ปลอดภัยก่อนเร็ว
การกระทำที่ย้อนกลับยากต้องผ่าน ConfirmDialog (focus เริ่มที่ “ยกเลิก”) · ทุกการบันทึกแจ้งผลด้วย toast · เมื่อบันทึกไม่สำเร็จ **ไม่ล้างค่าที่กรอก**

### 5. ใช้ได้ทั้งนิ้วและคีย์บอร์ด
โหมด comfortable ให้พื้นที่แตะ ≥ 44px · ทุกการกระทำเข้าถึงได้ด้วย Tab / Enter / Space / Esc · focus ring ชัดบนทุกพื้น · ไม่มีการกระทำที่ใช้ได้เฉพาะตอน hover หรือ double-click

### 6. สอดคล้องก่อนสร้างใหม่
ใช้ token และ component กลางก่อน ถ้าต้องต่างจากเดิม ให้เสนอเพิ่มเข้า design system (ดู Guides/Governance) แทนการแก้เฉพาะระบบ
ส่วนที่แต่ละระบบปรับได้ระบุไว้ชัดเจนใน Examples
